Alur Login & Registrasi

Sistem autentikasi SIMPAH menggunakan Supabase Auth dengan dukungan login via username maupun email, serta sistem kode undangan untuk onboarding petugas baru.

🔑 Alur Login

1

Buka Halaman Login

Pengguna mengakses /login atau membuka aplikasi PWA.

2

Masukkan Kredensial

Username saja (misal: admin1) atau email lengkap (admin1@simpah.dev). Sistem otomatis menambahkan domain @simpah.dev jika hanya username.

3

Verifikasi Supabase Auth

Kredensial diverifikasi oleh Supabase Auth. Jika berhasil, profil pengguna dimuat dari tabel profiles.

✓

Redirect Berdasarkan Role

Admin → Dashboard GIS  |  Eksekutif → Ringkasan Eksekutif
Koordinator → Validasi Data  |  Petugas/Warga → PWA Home

📝 Alur Registrasi

1

Buka Halaman Daftar

Klik "Buat akun baru" di halaman login → menuju /register.

2

Isi Data & Kode Undangan (Opsional)

Isi nama, username, email, dan password. Jika memiliki Kode Undangan dari Admin, role akan otomatis sesuai kode.

3

Trigger Database

Fungsi handle_new_user() dijalankan secara otomatis. Tanpa kode → role warga. Dengan kode valid → role + job_type sesuai kode.

✓

Akun Aktif

Pengguna bisa langsung login dan menggunakan fitur sesuai role yang ditetapkan.

Analitik & Laporan

📥 Tahap 1: Pencatatan

Petugas lapangan membuka form di PWA → pilih lokasi, kategori SIPSN, berat (kg) → simpan. Data masuk ke IndexedDB lokal dengan status verification_status: pending.

🔄 Tahap 2: Sinkronisasi

Saat perangkat terhubung internet, service worker memicu Background Sync. Data dikirim dari IndexedDB ke PostgreSQL Supabase melalui REST API.

✅ Tahap 3: Validasi

Admin atau Koordinator membuka halaman Validasi Data → memeriksa kewajaran data → menyetujui (approved) atau menolak (rejected) dengan catatan.

📊 Tahap 4: Pelaporan

Data yang sudah approved masuk ke perhitungan Ringkasan Eksekutif, Intervensi Wilayah, dan Laporan cetak resmi. Termasuk analisis gap terhadap target KLHK.

🛡️ Bagian 8

3 Layer Keamanan

Sistem keamanan berlapis yang melindungi data dari akses tidak sah di setiap tingkat aplikasi.

🔒

Layer 1: Database CHECK

Constraint di PostgreSQL memastikan hanya nilai role valid (warga, petugas, eksekutif, admin) yang bisa tersimpan. Mencegah injeksi role ilegal.

🛡️

Layer 2: Row Level Security

RLS di Supabase membatasi akses data di tingkat baris. Petugas hanya bisa melihat data miliknya sendiri, admin bisa melihat semua, eksekutif hanya data yang sudah approved.

🎛️

Layer 3: Frontend RBAC

Permission matrix di JavaScript mengontrol visibilitas menu dan fitur. Ditambah RBAC dinamis via tabel role_permissions untuk konfigurasi menu dashboard.
